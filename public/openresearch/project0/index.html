Goal

ActionPlan (condmdi_smpl) already denoises a dual stream: sequence CLIP text plus a dense per-frame action-plan. It does not see geometry. The long-term bet is to add a scene latent from VGGT-Ω run on egocentric TRUMANS video, so generated locomotion stays inside real rooms instead of an empty floor.

We did not start by training. We first asked whether we can even place existing HML3D motions into a TRUMANS room without walking through tables or leaking into mesh artifacts. That smoke test is what exists today.

Assumptions

  1. Scene conditioning is extra (cross-attention), not a replacement for the dual-stream RF model.
  2. Train data should be HML3D-272 placed into TRUMANS, not a first conversion of TRUMANS SMPL-X → 272.
  3. 272 features decode with condmdi_smpl/src/tools/streamer272_feats.py (Y-up). The copy under prepare/amasstools/ has the wrong layout and produces garbage scale.
  4. Lived space is the original actor’s root trajectory, not the entire watertight Scene_mesh AABB (that AABB includes a leaky hallway).
  5. GPU work runs in tmux session gpu (A100). Do not render on the login node.
  6. Ego that should look like TRUMANS uses the textured .blend, Blender 3.6.9. Mesh-tier OBJ is untextured clay and was only a crash fallback.

Occupancy from Scene_mesh (surface voxels, 5 cm). Walkable map is the 0.35–1.20 m furniture band, masked to the GT actor’s room AABB, then the largest connected component. Search samples open-floor cells (distance transform ≥ 0.18 m), not the path centroid (that sits on the coffee table). Hard constraint: root path stays in free space. Torso-vs-mesh is scored, not used as a hard reject (pelvis sits above table tops).

Decisions

ChoiceWhy
Place HML3D into TRUMANS, don’t convert TRUMANS→272 first Text + TAE already exist on HML3D-272. Scene alignment is the new problem.
Surface voxelization, not filled watertight A filled room mesh marks the interior solid and leaves only the leaky hallway as “free.”
Furniture-height free map (0.35–1.20 m) Chest-only (0.85–1.20 m) treats coffee tables as floor.
Mask to GT-lived room, then largest component Largest component of the full mesh is the hallway south of the room (z ≈ −4 m).
Plant path centroid, not frame 0 Walking clips otherwise slide into doorways.
Score toward GT path + clearance, sample open floor GT centroid is often on the table; tight-clearance scoring prefers alcoves.
Blend-tier ego (Blender 3.6.9) Mesh-tier is clay-white. Blend SIGABRT was from an older Blender path; 3.6.9 holds.
Ego = full clip @ 15 fps Smoke used to cap 40 frames / stride 4 / 10 fps (4 s). view3d was the whole motion.
GPU only in tmux gpu A100 allocation. Login node has no GPU / must not run Blender Cycles.

Failure modes we actually hit

Hallway placements. First three matches (M014345, M005381, 014461) were collision-free at z ≈ −3.5 to −4.2 — an artifact corridor out of the room. Filled occupancy + “largest free component” + 0.5 m clearance scoring.
Hollow voxels, room AABB from GT transl (mean z ≈ 1.75 m), largest component inside the room. Ignore any folder with z ≪ 0.
Walk-through-table. Next in-room matches (002838, M011081, 006325) sat at the GT centroid. Chest-height map missed the table; 3D joint collision was soft.
Furniture band includes table height. Root-in-free-space is hard. Sample distance-transform open cells. Path length cap 2.5 m for this room.
White ego. Mesh-tier OBJ + emissive gray + camera fill. Not the TRUMANS look.
Load the .blend, strip the baked actor, add SMPL-X, Cycles OPTIX. This particular room’s walls really are pale; wood door / tiles / chair are the tell.

How big can this dataset get?

Not 27k clips × 688 sequences. Placement is per unique mesh (~100 TRUMANS scenes). This room’s diameter kills long walks.

RecipePer furnished room like this× ~100 scenes
Locomotion, 1 pose / clip (smoke recipe) ~10² clips (7.5% of 4–10 s walks here) ~10k–100k
Same, keep several SE(2) poses ~10²–10³ tuples maybe 2–5×
Any geometrically free HML3D (wave, stand, mid-air sit) ~10⁴–10⁵ 10⁶+, mostly junk

Real caps: path length vs room, semantics (chairs/stairs/objects), and Blender time if every tuple needs ego RGB. HUMANISE-scale loco placement is the honest target.
